# Tachyon Lab Curriculum: the Learn track

It defines **what the Learn track teaches, how every lesson is written, and when each lesson ships.**

The simulations show what happens. The lessons explain **why**. A learner should be able to read a lesson, open the linked simulation, and understand what they see.

The full topic list lives in code, in [`apps/web/src/lib/learn/curriculum.ts`](../apps/web/src/lib/learn/curriculum.ts). It is the single source of truth: the Learn index page is built from it, and a topic counts as _written_ when a lesson file with the same slug exists. This document explains the plan around it.

---

## 1. Scope

**88 topics: 46 classical, 42 quantum**, grouped into 18 sections, in teaching order. Two tiers:

| Tier         | Meaning                                                                                       | Topics |
| ------------ | --------------------------------------------------------------------------------------------- | ------ |
| **Core**     | Needed to understand a v1 simulation module. Written alongside that module ("lesson-first"). | 60     |
| **Extended** | Completes the subject but no v1 module depends on it. Written after launch, in any order.     | 28     |

Core = 34 classical + 26 quantum. Extended = 12 classical + 16 quantum.

The tier is a per-topic field to add to `curriculum.ts` (`tier: 'core' | 'extended'`); until then the table in §4 is the reference.

**"Every topic" means every topic in the map, written over time.** Writing 88 lessons well takes months, so the plan is to publish the map at once (learners see what is coming) and fill it in module by module. A topic with no lesson yet is shown as _planned_, never hidden and never faked.

**Reading the tables below.** Lessons are written alongside the simulations they support, in build order: _Phase 1_ is the classical track, _Phase 2_ waves, _Phase 3_ one-dimensional quantum mechanics, _Phase 4_ qubits. Module codes: **C1** Motion & integrators, **C2** Oscillators & phase space, **C3** Lagrangian sandbox, **C4** Orbits & central forces, **C5** Coupled oscillators & chaos, **B1** Waves & Fourier, **A** 1D wavefunction playground, **B** Qubit & Bloch sphere, **E** Two-level systems & Rabi oscillations.

## 2. How every lesson is written

**Goal: a motivated beginner who has only the listed prerequisites can follow every step.**

### Principles

1. **Plain words first, symbols second.** Say it in a sentence before writing the equation.
2. **One idea per lesson.** About 700–1,000 words. If it needs more, split it.
3. **Derive, don't declare.** No "it can be shown that". Every equation is built step by step from earlier ones, and every symbol is defined where it first appears, with units.
4. **Concrete before abstract.** A picture or familiar example first (a braking car, a swing), then the general law.
5. **Numbers you can check.** Every worked example uses real numbers, and the answer is verified a second way.
6. **Name the traps.** A "Common mistakes" section for the errors learners actually make.
7. **Make the reader do something.** Predict before reading, explain steps while reading, try a faded example, then "Check yourself". Answers stay collapsed until asked for.
8. **Connect to the lab.** Say which simulation to open and what to look for.
9. **Honest about limits.** Say where an approximation stops being valid.

### Standard structure (v2, adopted 8 Nov 2026)

Every lesson has these sections, in order (tests enforce them). v2 adds **Predict first** and **Try one yourself**, based on research on pretesting, self-explanation and faded worked examples.

1. **The big picture:** three sentences: what this is, why it matters, what you will be able to do.
2. **Predict first:** one question to answer *before* reading (a sketch, a choice, or a number). The answer is revealed at the end of the lesson.
3. **Build the intuition:** an everyday picture or analogy.
4. **The math:** the derivation, step by step, with 1–2 **"Why does this step follow?"** prompts whose answers are collapsed.
5. **Worked example:** real numbers, solved, then checked a second way.
6. **Try one yourself:** the same kind of problem with some steps left blank (faded); answer and full solution collapsed.
7. **Common mistakes:** each linked to its misconception preset in the lab where one exists.
8. **Check yourself:** 3–5 questions, mixing recall with "explain why". These also feed the spaced review queue.
9. **Answers:** short, with the reasoning, not just the number, including the answer to *Predict first*.
10. **Where this shows up in the lab:** links that open the simulation at a specific preset, and the next lesson.

Length guideline rises to about **700–1,000 words**; split the lesson if it grows past that.

**How the sections are authored.** To keep one source of truth, three sections are **generated by the lesson page from frontmatter** rather than written in the Markdown body: **Predict first** (from `predict`), **Check yourself** and **Answers** (from `questions`). The review queue reads the same data, so a question can never differ between the lesson and `/review`. The Markdown body holds the other seven sections as `##` headings, in this order: _The big picture_, _Build the intuition_, _The math_, _Worked example_, _Try one yourself_, _Common mistakes_, _Where this shows up in the lab_. Collapsed content ("Why does this step follow?", the faded example's answer) is written as HTML `<details><summary>…</summary>…</details>` inside the body; the build pipeline allows it because lesson files are trusted repository content.

### Frontmatter

```yaml
---
title: Projectile motion
summary: One sentence shown in the index.
level: beginner # beginner | intermediate | advanced
minutes: 10 # honest reading time
prerequisites: [classical/describing-motion] # track/slug; must exist; no cycles
sim: /lab/projectile # optional: the simulation to open
status: draft # draft | reviewed
predict: # the "Predict first" question
  type: choice # sketch | choice | numeric
  prompt: Two balls are dropped from 20 m, one twice as heavy. With no air, which lands first?
  options: [The heavy one, The light one, Same time]
  answer: Same time
  reveal: Gravity pulls harder on the heavy ball, but it also has more inertia, and the two effects cancel exactly.
questions: # "Check yourself" items, also used by the review queue (/review)
  - id: q1
    type: numeric # numeric | choice | explain
    prompt: A ball is thrown straight up at 12 m/s. How high does it rise? (g = 9.8 m/s²)
    answer: 7.35
    tolerance: 0.05
    unit: m
    solution: v² = 2gh, so h = 12² / (2 × 9.8) = 7.35 m.
  - id: q2
    type: explain
    prompt: Why doesn't the horizontal speed change when there is no drag?
    model: No horizontal force acts, so by Newton's second law the horizontal acceleration is zero.
---
```

### Accuracy and review

Physics errors destroy trust, so lessons have a review path:

- **Draft.** Lessons may be drafted with AI help. A draft shows a visible **"Draft: not yet reviewed"** label.
- **Verify the numbers.** Every worked example and quoted value is checked by code or a test before merge.
- **Review (the builder-learner step).** The builder derives the key steps by hand, fixes anything unclear, and adds one "what confused me" note. Only then does `status` become `reviewed` and the label disappears. This is the same rule as the module roadmap: no skipping the understanding.
- **Notation is consistent.** One notation page defines the symbols; lessons never reuse a symbol for a different quantity.
- **Report an error.** Every lesson links to the issue tracker.

## 6. Definition of done for a lesson

- [ ] Frontmatter complete; slug is in `curriculum.ts`; prerequisites exist.
- [ ] All ten standard sections present (v2), including Predict first and Try one yourself.
- [ ] `predict` and `questions` frontmatter present and valid; numeric answers verified by code.
- [ ] Each common mistake links to its misconception preset where one exists.
- [ ] Every symbol defined with units; notation matches the notation page.
- [ ] Every number in worked examples verified by code or test.
- [ ] "Check yourself" answers include reasoning.
- [ ] Linked simulation (if any) exists and the lesson says what to look for.
- [ ] Builder has derived the key steps by hand (`status: reviewed`).
- [ ] Reading time honest; reading level fits the stated prerequisites.

## 7. How to add a lesson

1. Make sure the topic is in `curriculum.ts` (add it if not).
2. Copy `apps/web/src/content/learn/_template.md` to `apps/web/src/content/learn/<track>/<slug>.md`.
3. Write it to the standard in §2, with `status: draft`.
4. Run `pnpm test` (content tests) and `pnpm dev` to read it in the browser.
5. After your own review, set `status: reviewed`.
